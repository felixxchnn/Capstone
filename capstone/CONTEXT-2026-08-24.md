## 1. What the project is

**Research question.** Do frozen Geneformer embeddings outperform a ridge-on-PCA-expression
baseline at predicting CRISPR gene dependency across held-out cancer cell lines, measured
by per-target Spearman correlation?

**Answer: no, and the deficit is now quantified.** This is a clean negative result with
identified mechanisms, not a failed experiment.

**Setting.** High-school capstone, British Columbia, Canada. Two-person team — Felix
(primary, does all execution) and Leo He. Supports university applications, so the public
repository is itself a deliverable. Depth and authenticity matter more than breadth.

Splits are deterministically regenerable from the seed. Sibling cell lines from one donor
cannot straddle the split — `checks.py` fails the run if any group does. Splits are

Alpha is selected by grouped 5-fold cross-validation inside the training set when
evaluating on val; when evaluating on test, alpha is selected on val. There is no
tuning-regime versus evaluation-regime mismatch.

## 3. The Geneformer configuration

| Setting | Value |
|---|---|
| Checkpoint | **`Geneformer-V2-104M_CLcancer`** |
| What that is | The V2 104M model after continual learning on ~14M **cancer** transcriptomes |
| Context length | 4,096 tokens |
| Special token | True |
| Pooling | CLS, final layer (`emb_layer = -1`) |
| Output dimensionality | 768 |
| `count_source` | **`reconstructed_from_log_tpm`** — confirmed from the Kaggle execution log |
| Ensembl-mapping attrition | **Zero.** 18,460 of 18,460 genes mapped. |

**Why the checkpoint matters.** Standard Geneformer checkpoints deliberately exclude
malignant cells from pretraining. This project used the cancer-domain variant — the
best-suited published checkpoint for DepMap cell lines. That pre-empts the strongest
objection to a negative result and should be stated explicitly in the presentation.

**Why `count_source` matters.** Geneformer expects raw read counts; DepMap ships
log2(TPM+1). The preparation script reconstructs `TPM = 2^log_tpm − 1` as a stand-in
because a real expected-counts file was unavailable. Geneformer *ranks* genes by relative
abundance, and TPM carries gene-length normalisation that true counts do not, so the input
ranking is systematically distorted relative to what the model was pretrained to read.
**This is a live alternative explanation for part of the deficit and belongs in the scope
statement.** It is a limitation, not an error — it is documented and disclosed.

## 4. Results — all verified, all reproducible from the repository

Evaluated on the **val** split: 170 held-out cell lines, 4,297 targets, scored by
`baseline.evaluate` for every model so the measurement is identical throughout.

### 4.1 Model ladder

| Model | Selected α | Spearman mean | Median | R² mean |
|---|---|---|---|---|
| `ridge_pca` — StandardScaler → PCA(200) → Ridge on expression | 100,000 | **0.2356** | 0.2302 | 0.0690 |
| `ridge_head` — StandardScaler → Ridge on 768-dim Geneformer CLS | 3,162 | **0.2047** | 0.1980 | 0.0523 |
| `lineage_mean` — tissue-identity control | — | 0.1500 | — | 0.0124 |
| `mlp_head` — StandardScaler → MLPRegressor(256) on embeddings | 0.1 | **0.1274** | 0.1177 | −0.1217 |
| `global_mean` — null | — | **undefined** | — | −0.0066 |

`global_mean`'s Spearman is undefined for all 4,297 targets because a constant prediction
has no rank variance. Correct behaviour, not a bug.

Baseline quartiles: q25 0.1439, q75 0.3230, 97.39% of targets positive.
Head quartiles: q25 0.1136, q75 0.2884, 95.93% of targets positive.

### 4.2 Deltas

| Comparison | Δ |
|---|---|
| Geneformer ridge head vs expression baseline | **−0.0309** |
| Geneformer ridge head vs lineage control | +0.0547 |
| Expression baseline vs lineage control | +0.0856 |
| MLP head vs expression baseline | −0.1082 |
| MLP head vs lineage control | −0.0226 |

### 4.3 Uncertainty — bootstrap over held-out cell lines

1,000 resamples of the 170 held-out cell lines with replacement, models held fixed,
both models sliced by the same indices within each resample so the pairing is preserved.
Percentile intervals.

| Quantity | Bootstrap mean | 95% CI | SE |
|---|---|---|---|
| `ridge_pca` | 0.2344 | [0.2188, 0.2505] | 0.0080 |
| `ridge_head` | 0.2036 | [0.1881, 0.2198] | 0.0079 |
| `lineage_mean` | 0.1490 | [0.1330, 0.1654] | 0.0086 |
| **Δ (head − baseline)** | **−0.0308** | **[−0.0365, −0.0255]** | **0.0028** |
| **Share of expression-over-lineage gain recovered** | **0.6373** | **[0.5561, 0.7080]** | 0.0390 |

**The interval excludes zero decisively.**

**Why the delta's interval is so much narrower than the individual models'.** Both models
are evaluated on identical resamples, so their bootstrap draws correlate at r ≈ 0.94 and
the shared sampling noise cancels in the paired difference. Independent resampling would
have given SE ≈ 0.011, four times wider, and the interval would have brushed zero. The
pairing, not the sample size, is what makes this difference resolvable at n = 170.

**Ties disclosure — must travel with these numbers.** Resampling with replacement
duplicates cell lines, introducing ties into the rank correlation. `spearmanr` and
`rankdata` resolve ties by averaging, so the computation is correct, but ties attenuate
the correlation slightly. Measured effect: bootstrap means fall below the point estimates
by 0.0012 (baseline), 0.0011 (head) and 0.0010 (lineage) — about half a percent. Because
the attenuation is near-identical across models it cancels in the difference, which moves
by 0.0001 (point −0.0309, bootstrap −0.0308). The bias is present in the individual
figures and absent from the reported quantity.

**Share-of-gain caveat.** `lineage_mean` is not a zero-information floor, so 63.7% is a
share of the gain over tissue identity, not of all available signal. It also inherits the
noise of three estimates rather than two.

### 4.4 Paired test across targets

| Quantity | Value |
|---|---|
| Targets paired | 4,297 of 4,297 (none dropped) |
| Mean paired difference | −0.0309 |
| Median paired difference | −0.0304 |
| Targets where head wins | **24.65%** |
| Exact ties | 0 |
| Wilcoxon statistic | 1,664,390 |
| Wilcoxon p | 1.25 × 10⁻²⁸⁸ |

**Caveat — must travel with the p-value.** Gene dependencies are strongly correlated
(co-essential genes move together), so the number of independent targets is far below
4,297 and the test's independence assumption is violated in the direction that inflates
significance. Report it because a reader will look for it, not as the strongest evidence.
The bootstrap over cell lines is stronger, because cell lines were sampled independently
and targets were not.

### 4.5 Correlation of per-target performance

| Quantity | Value |
|---|---|
| Pearson r between the two per-target ρ vectors | **0.9283** |
| Spearman ρ between them | 0.9189 |

**This settles a question earlier documents marked "suggestive, not proven."** The two
models succeed and fail on the same targets. Combined with the head winning only a quarter
of targets, and a median paired difference (−0.0304) nearly equal to the mean (−0.0309),
the pattern is a broadly uniform downward shift of the same underlying signal — not
different information. That is exactly what input truncation predicts.

### 4.6 Effective degrees of freedom — capacity, matched by measurement

Convention: trace of the ridge hat matrix, `df(α) = Σᵢ sᵢ²/(sᵢ² + α)`, where sᵢ are the
singular values of the **centred design matrix the Ridge estimator receives**, on the
**800 training rows only**. Both models measured by one function.

| Model | Design | trace(Z'Z) | Selected α | **Effective df** |
|---|---|---|---|---|
| `ridge_pca` | 800 × 200 | 11,155,960.73 | 100,000 | **49.71** |
| `ridge_head` | 800 × 768 | 614,400.00 | 3,162 | **51.78** |

**The convention matters and must be stated.** scikit-learn's `PCA.explained_variance_`
returns sᵢ²/(n − 1). Substituting it into the formula rescales α by a factor of n − 1
(here ~800) and produces a plausible-looking number wrong by two orders of magnitude.

**This is the strongest new result.** The two alphas were selected independently, differ by
a factor of 32, and sit on feature spaces differing by nearly four times in width — yet the
resulting capacities agree within 4%. Nothing was tuned to produce that. It establishes by
measurement what the comparison previously assumed: the two models had equivalent capacity,
and the baseline still won. It also suggests roughly 50 effective parameters is what 800
training cell lines support on this task, largely independent of the representation.

Full df sweeps across the 13-point grid are in `data/processed/analysis_results.json`.

## 5. How to frame the result

**Scope it precisely.** Frozen Geneformer CLS embeddings with a linear ridge head do not
outperform ridge-on-PCA-expression for per-target Spearman prediction of CRISPR dependency
across held-out DepMap cell lines. This is *not* "Geneformer doesn't work."

**Untested and to be stated as such:** fine-tuning, alternative pooling, real expected
counts. (Concatenation and random projection are planned — see §7.)

**Two identified mechanisms for the deficit:**

1. **Input truncation — the largest and most defensible.** The baseline sees all 18,460
   protein-coding genes. Geneformer's rank-value encoding sees at most 4,096 per cell line,
   roughly the top 22% by rank. A hard information asymmetry.
2. **Pseudo-counts.** `count_source = reconstructed_from_log_tpm`. Gene-length-normalised
   input distorts the ranking Geneformer was pretrained to read.

A third candidate — Ensembl-mapping attrition — has been **eliminated**. Attrition was zero.

**Most interpretable statement of the headline:** the embeddings recover 63.7%
[55.6%, 70.8%] of the gain that raw expression buys over knowing the tissue alone. Far more
readable than −0.0309, and it foregrounds the positive finding embedded in the negative
one: the embeddings do carry substantial cell-line-specific signal beyond lineage.

### 7.2 Remaining experiments — only two

**E3 (MLP head) is already complete.** It scored 0.1274, below the tissue-identity control,
with 83% of targets at negative R². The deficit is not head-specific: a nonlinear head on
the same frozen embeddings is dramatically worse than a linear one, which is what 800
training rows against a 256-unit hidden layer would predict. This strengthens the linear
ridge as the fair test of the representation.

*One caveat before that goes on a slide:* the MLP's record carries
`"alpha_at_grid_boundary": true` — it selected 0.1, the ceiling of `MLP_ALPHAS =
[1e-3, 1e-2, 1e-1]`. Structurally the same situation as the truncated ridge grid the
project's methodological narrative is built on. But the sweep was **flat** (0.1134 /
0.1123 / 0.1135, range 0.0012), where the ridge sweep had been monotonically accelerating.
Extending the grid almost certainly will not rescue it. One confirmatory run with a wider
grid would let the slide say "we checked" rather than "we think." ~20 minutes.

**E1 — random projection control at 768 dims.** `GaussianRandomProjection(n_components=768,
random_state=RANDOM_SEED)` on standardised expression, then the identical ridge head and
its own 13-point α grid. Asks whether pretraining bought anything over a random bottleneck
of the same width — a more fundamental question than the MLP asked, at similar cost.

*Prepare for the outcome the older documents treat as unlikely.* Under heavy shrinkage, a
random 768-dim linear sketch of 18,460 standardised genes may well match or beat PCA-200,
and therefore beat Geneformer. If so that is a **better** slide, not a broken one: "a random
linear compression of expression outperforms a pretrained cancer transformer at matched
width." Prepare that framing in advance.

*Note on scale:* sklearn's `GaussianRandomProjection` draws components from N(0, 1/n_components),
so projected columns land at variance ≈ 18,460/768 ≈ 24 — between the head's 1.0 and the
PCA block's eigenvalues. E1 therefore needs its own α grid, and the selected α must be
checked as interior.

**E2 — concatenation `[expression PCs ‖ embeddings]` through the same ridge head.**
Asks whether the embeddings carry anything expression does not.

**⚠ E2 as originally specified will probably produce an uninterpretable result.** In
`run_ridge_pca`, the PCA scores are **not** re-standardised, so those 200 columns carry
their eigenvalues as variances (up to thousands). In `run_ridge_head`, the 768 embedding
columns are standardised to unit variance. Concatenate them under a **single scalar α** and
the high-variance PC directions are shrunk proportionally far less. The likely outcome is
ρ_concat ≈ ρ_baseline with no way to distinguish "the embeddings added nothing" from "the
embeddings were shrunk out of existence." That the two models independently selected alphas
32× apart is direct evidence the spectra are incompatible under one α.

Fixes, ascending cost: (a) standardise both blocks to comparable scale and say so;
(b) report the fraction of fitted coefficient norm attributable to each block as a
diagnostic; (c) block-wise α — the correct experiment, more work. Minimum honest version is
(a) + (b), noting that (a) changes the baseline's inductive bias and so wants a
whitened-PCs-only control, which adds a model to val.

**Then freeze the model set**, in writing, dated.

### 7.3 Performance — worth doing before E1

The bootstrap calls `baseline.per_target_spearman`, which loops in Python over 4,297 targets
calling `spearmanr` on 170 values each: ~12.9 million calls per 1,000-resample run,
single-threaded, **30–45 minutes**. E1, E2 and the test run mean another 2–3 hours of waiting.

A vectorised fast path is available and was deliberately declined for the first run. Ridge
predictions contain no NaNs, so per-column missingness is determined entirely by `y_true`
and is fixed across resamples: fully-observed targets can be ranked and correlated as one
vectorised block, with partially-missing columns falling back to the loop. Realistically
8–15× faster. **If built, it must ship with an assertion that it matches
`per_target_spearman` exactly on the unresampled data before it is allowed to run** — the
project's discipline is that the metric is imported from `baseline.py`, not reimplemented.

## 8. Standing methodological cautions

**Val-set optimism.** Five models have now been scored on val: `ridge_pca`, `ridge_head`,
`mlp_head`, `lineage_mean`, `global_mean`. E1 and E2 would make seven. Selecting among
seven on 170 lines inflates the reported numbers.

*The clean defence:* the headline comparison (baseline vs head) was fixed before E1 and E2
existed. Label it the pre-specified comparison and E1/E2 as exploratory controls. That
preserves the headline's integrity regardless of how many controls are added, and it costs
one sentence.

**Reproducibility is asymmetric between the two arms, and this must be stated rather than
discovered.** The baseline arm is reproducible end to end from the public repository — a
fresh clone reproduces `baseline_results.json` byte-identically. The Geneformer arm is not:
the embeddings were generated in an interactive Kaggle GPU session and ship as a data
artifact, so the head can be refitted and rescored exactly but the embeddings themselves
cannot currently be regenerated from the repository. The checkpoint, context length,
pooling and input provenance are all recorded, so the procedure is documented even where it
is not re-executable. This is a methods limitation, not a cosmetic defect.

**The alpha-grid lesson, twice over.** The original ridge grid was `[1, 10, 100, 1000,
10000]` and the inner-CV sweep was still accelerating at the ceiling — α=10,000 was chosen
because it was the largest offered, not because it was best. The corrected 13-point grid
extends to 1,000,000 and peaks at a genuine interior optimum of 100,000. Spearman moved only
+0.0043 (0.2313 → 0.2356) but **R² rose 63%** (0.0423 → 0.0690): heavy shrinkage barely
changed the *ordering* of predictions while substantially fixing their *scale*. Excellent
material on why metric choice defines "better."

**Always verify the selected α is interior to the grid.** `run_ridge_head` has a
`alpha_at_grid_boundary` guard; `run_ridge_pca` does **not**. The function that actually
suffered the bug is the one without the check. Harmless now (100,000 is interior) but it
matters for E1 and E2, which introduce new feature spaces with new natural α scales.

**Hand-computed figures in comments have now failed twice.** Both the α grid and the
effective-df table were plausible-looking numbers that no code produced. Any figure quoted
in the write-up should be traceable to a committed artifact.

**Do not add scope.** Fine-tuning, alternative pooling, and the CPIC/PharmGKB
pharmacogenomic safety layer are all cut. Six weeks does not accommodate them alongside a
proper test-set run and a rehearsed presentation.
